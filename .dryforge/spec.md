# spec — 코딩테스트 코치

## 목표와 이유

혼자 코딩테스트 문제를 풀다 막히면 지금은 구글·챗지피티에게 하나씩 물어 가며 이해한다.
그런데 풀이 파일에는 코드만 남고 어디서 막혔는지, 핵심 아이디어가 뭐였는지가 남지 않아 비슷한 문제를 다시 만나면 처음부터 다시 찾게 된다.
이 저장소 안에서 Claude Code로 부르는 코치를 만들어, 정답 대신 단계별 힌트를 주고, 푼 기록을 남기고, 다시 풀 문제와 실력 변화를 알려 준다.

## 범위

- 넣는 것: 단계별 힌트 코치, 풀이 파일 머리말 기록, 유형별 노트, 다시 풀기 목록, 주간 점검 문제, 실력 숫자 요약, 저장·커밋·푸시.
- 빼는 것: 웹 화면, 서버, 데이터베이스, 대시보드(사용자가 한 명이다).
- 빼는 것: 예전 풀이 파일 일괄 정리(이름 바꾸기·확장자 붙이기·중복 정리). 예전 파일은 다시 풀 때만 옮긴다(아래).
- 언어는 파이썬 풀이만 다룬다.

## 코치 대화 흐름

1. 코치를 부르면 먼저 알림을 보여 준다(아래 순서).
   - 끝나지 않은 문제가 있으면: "풀던 문제 이어서 할래요?" 이어 하면 본 힌트 단계와 시작 시각을 그대로 잇는다. 안 한다고 하면 그 문제를 `못 풀었음`으로 기록한다.
   - 오늘까지 다시 풀 문제가 있으면 개수와 목록(가장 오래 밀린 것부터).
   - 점검 차례이면 "점검 볼 때예요".
   - 사용자가 다시 풀기 / 점검 / 새 문제 중 고른다. 알림은 강요하지 않는다.
2. 문제 입력: 사용자가 링크를 준다. 코치가 링크를 읽어 문제를 파악한다. 로그인이 필요하거나 읽지 못하면 문제 글을 붙여 달라고 한다. 문제를 보여 준 순간 시간을 재기 시작한다.
3. 힌트 단계(아래)를 사용자가 "다음"이라고 할 때만 한 단계 올린다.
4. 사용자는 언제든 코드를 보여 줄 수 있다. 코치는 그 코드를 문제의 예제 입력으로 실제로 실행해 어느 예제가 틀렸는지 알려 준다. 고치는 것은 사용자가 한다(4단계 전에는 틀린 줄을 짚지 않는다).
5. 모든 예제가 맞으면 끝. 사용자가 그만두면 `못 풀었음`으로 끝.
6. 끝나면 코치가 유형(폴더)·막힌 곳·핵심·유형 노트 초안을 제안하고, 사용자가 고치거나 좋다고 하면 확정한다.
7. 풀이 파일을 저장하고, 코치가 쓴 파일만 한 커밋으로 묶어 커밋하고 GitHub에 푸시한다. 따로 확인을 묻지 않는다.

## 힌트 단계

| 단계 | 내용 |
|---|---|
| 0 | 힌트 없이 혼자 풀기 |
| 1 | 유형 ("최소 개수 + 작은 금액의 답으로 큰 금액의 답 → dp") |
| 2 | 질문으로 이끌기 ("11을 만드는 최소 개수를 10·9·6의 답으로 나타낼 수 있을까?") |
| 3 | 의사코드(뼈대) |
| 4 | 내 코드에서 틀린 줄 짚기 |
| 5 | 정답 코드 + 설명 |

- 단계는 사용자가 "다음"이라고 할 때만 오른다. 코치가 막힌 것 같다고 판단해서 올리지 않는다.
- 정답 코드는 5단계에서만 보여 준다. 그 전에는 어떤 형태로도 완성 코드를 주지 않는다.
- 중간에 궁금한 것을 묻거나 코드를 예제로 돌려 보는 것은 단계를 올리지 않는다.
- 기록되는 값은 그 시도에서 본 가장 높은 단계다.

## 점검 문제 (실력 확인)

- 주기: 마지막 점검에서 7일이 지나면 코치를 부를 때 "점검 볼 때예요"라고 알린다. 점검을 한 번도 안 했으면 첫 기록일에서 7일이 지난 때부터다. 할지는 사용자가 고른다.
- 기록된 유형이 하나도 없으면 점검 알림을 하지 않는다.
- 유형 고르기: 사용자가 푼 적 있는 유형 중 가장 오래 점검하지 않은 유형(점검한 적 없는 유형이 먼저, 같으면 목록 순서). 이렇게 모든 유형을 돌아가며 본다.
- 문제 고르기: 릿코드의 무료 쉬움~보통 문제 중 이 저장소에 없는 문제(예전 파일 포함, 번호로 확인). 코치는 링크가 실제로 열리는지 확인한 뒤 낸다.
- 통과: 힌트 0단계, 30분 이내, 풀었음. 셋 중 하나라도 아니면 미통과다. 30분이 지나도 계속 풀 수 있지만 미통과로 기록한다.
- 점검 중 "다음"을 말하면 "점검 중이에요, 힌트를 보면 미통과예요. 그래도 볼래요?"라고 한 번 묻고, 본다고 하면 보여 주고 미통과로 기록한다.
- 점검 문제도 일반 풀이 파일로 저장되고, 다시 풀기 규칙도 똑같이 적용된다.
- 점검이 끝나면 숫자 요약을 자동으로 보여 준다.

## 걸린 시간

- 문제를 보여 준 때부터 예제가 모두 맞거나 그만둘 때까지 그냥 잰다. 쉬는 시간도 포함한다. 멈춤 기능은 없다.
- 창을 닫았다가 이어 하면 처음 시작 시각부터 계속 센다.
- 분 단위로 내림해 기록한다(30분 판정은 내림한 값 ≤ 30).

## 다시 풀기 일정

일정은 한 문제의 기록 줄 목록만으로 계산한다(따로 저장하지 않는다).

- 시도 결과 "통과" = 풀었음이고 힌트 2단계 이하. "실패" = 힌트 3단계 이상이거나 못 풀었음.
- 첫 시도가 통과면 `다음 복습: 없음`.
- 실패하면 그 시도 날짜 + 3일.
- 복습 중 통과하면 다음 간격으로: 3일 뒤 통과 → +7일, 7일 뒤 통과 → +30일, 30일 뒤 통과 → `없음`(끝).
- 복습 중 실패하면 다시 +3일부터.
- 날짜는 실제로 푼 날부터 센다.
- 복습 날이 지난 문제는 목록에 계속 남고, 가장 오래 밀린 것부터 보여 준다.
- 끝난(`없음`) 문제를 사용자가 스스로 다시 풀어도 기록 줄은 쌓이고, 같은 규칙으로 다시 계산한다.

계산 방법: 마지막 실패 이후 연속 통과 횟수 k로 다음 간격을 정한다. k=0(마지막이 실패)→3일, k=1→7일, k=2→30일, k≥3→없음. 단 실패가 한 번도 없는 문제는 `없음`.

## 실력 숫자 요약

"실력 보여 줘"라고 하면, 또 점검이 끝나면 보여 준다.

- 유형별 점검 통과 여부(가장 최근 점검 결과와 날짜, 점검 안 했으면 "아직").
- 유형별 평균 힌트 단계: 최근 4주, 주마다.
- 유형별 평균 걸린 시간: 최근 4주, 주마다.
- 푼 문제 수: 주마다, 유형별.
- 머리말이 있는 파일만 센다. 예전 파일(머리말 없음)은 세지 않는다.
- 주는 월요일 시작(조정 가능).

## 유형 노트

- 파일: `notes/patterns.md`. 유형마다 절 하나.
- 문제를 끝낼 때 코치가 "이런 문장이 나오면 이 유형" 식으로 한두 줄을 제안하고, 사용자가 고치거나 좋다고 해야 들어간다. 사용자가 빼자고 하면 넣지 않는다.

## 파일 자리와 이름

- 자리: `<사이트 폴더>/<유형>/<번호>_<영어 이름>.py`
  - 사이트 폴더: `leetcode`, `programmers`, `baekjoon`.
  - 영어 이름: 소문자, 단어 사이 `_`. 릿코드는 영어 제목, 프로그래머스·백준은 한글 제목을 짧게 영어로 옮긴 이름.
  - 예: `leetcode/dp/322_coin_change.py`, `programmers/dfs/43165_target_number.py`.
- 유형이 여럿이면 대표 하나가 폴더가 되고, 머리말 `유형:` 줄에 모두 적는다(대표가 맨 앞).
- 다시 풀 때 사용자가 대표 유형을 바꾸면 파일을 새 유형 폴더로 옮기고(git 기록이 이어지게), 그 문제의 예전 기록까지 모두 새 유형으로 센다.
- 다시 풀 때 코드는 새 코드로 바뀐다. 예전 코드는 git 기록에 남는다.
- 예전에 올린 파일(새 규칙이 아닌 파일)의 문제를 다시 풀면, 그 파일을 새 규칙 자리로 옮기고 머리말을 붙여 이어 쓴다. 같은 문제 파일이 두 곳에 생기지 않는다.

### 유형 목록 (폴더 이름, 한 곳에서만 관리)

| 폴더 | 뜻 |
|---|---|
| dp | 동적 계획법 |
| bfs | 너비 우선 탐색 |
| dfs | 깊이 우선 탐색 |
| greedy | 그리디 |
| implementation | 구현 |
| stack_queue | 스택·큐 |
| hash | 해시 |
| sort | 정렬 |
| binary_search | 이분 탐색 |
| two_pointer | 투 포인터 |
| heap | 힙(우선순위 큐) |
| graph | 그래프(최단 경로 등) |
| string | 문자열 |
| brute_force | 완전 탐색 |

목록에 없는 유형은 사용자가 승인하면 목록에 더한다. 목록 밖 이름으로 파일을 만들지 않는다.

## 머리말 (풀이 파일 맨 위) — 정확한 모양

```
# 릿코드 322. Coin Change
# https://leetcode.com/problems/coin-change/
# 유형: dp
# 막힌 곳: 금액마다 동전을 다 해 봐야 하는 줄 몰랐음
# 핵심: dp[i] = min(dp[i - coin] + 1)
# 기록:
#   2026-10-19 힌트 3단계 · 42분 · 풀었음
#   2026-10-22 힌트 1단계 · 18분 · 풀었음
#   2026-10-26 힌트 0단계 · 27분 · 풀었음 · 점검 통과
#   2026-11-02 힌트 4단계 · 55분 · 못 풀었음 · 점검 미통과
# 다음 복습: 2026-10-29

class Solution:
    ...
```

- 1줄: `# <사이트 이름> <번호>. <원래 제목>`. 사이트 이름은 `릿코드`·`프로그래머스`·`백준` 중 하나.
- 2줄: `# <문제 링크>`.
- `# 유형: <유형>[, <유형>...]` — 모두 유형 목록 안의 이름, 첫째가 폴더와 같다.
- `# 막힌 곳: <글>`, `# 핵심: <글>` — 비어 있으면 `없음`. 다시 풀 때 사용자가 확인한 새 내용으로 바꿀 수 있다.
- `# 기록:` 다음 줄부터 기록 줄, 오래된 것이 위. 기록 줄 모양:
  `#   YYYY-MM-DD 힌트 N단계 · M분 · (풀었음|못 풀었음)[ · 점검 (통과|미통과)]` (N은 0~5, M은 0 이상 정수, 구분자는 ` · `).
- `# 다음 복습: (YYYY-MM-DD|없음)` — 기록 줄로 계산한 값과 항상 같아야 한다.
- 머리말 다음 빈 줄 한 줄, 그 아래 코드.
- 기록 줄은 지우거나 고치지 않고 아래에 더하기만 한다.

## 진행 중인 문제 기억

- 창을 닫아도 이어 할 수 있게 진행 중인 문제 하나를 저장소 안 로컬 파일에 기억한다(사이트, 번호, 제목, 링크, 시작 시각, 본 최고 단계, 점검 여부). 이 파일은 깃에 올리지 않는다.
- 동시에 진행 중인 문제는 하나다. 새 문제를 시작하려 할 때 진행 중인 것이 있으면 먼저 이어 할지 묻는다(1번 흐름과 같음).
- 끝나거나 못 풀었음으로 기록되면 지운다.

## 저장·커밋·푸시

- 커밋에는 코치가 이번에 쓰거나 옮긴 파일(풀이 파일, `notes/patterns.md`, 유형 목록을 늘렸다면 그 파일)만 넣는다. 사용자가 따로 고치던 파일은 넣지 않는다.
- 커밋 메시지: `solve: [<대표 유형>] <사이트 영어 이름> <번호>` (예: `solve: [dp] leetcode 322`). 다시 풀기는 `review:`, 점검은 `check:`로 시작한다(조정 가능).
- 지금 브랜치(main)로 푸시한다. 확인을 묻지 않는다.
- 푸시가 실패하면 실패했다고 알리고 커밋은 그대로 둔다. 올라갔다고 말하지 않는다.

## 예외 규칙

- 링크를 못 읽음 → 문제 글 붙여넣기 요청. 붙여 넣은 글에 예제가 없으면 예제를 달라고 한다(예제 없이 맞았다고 하지 않는다).
- 문제 사이트나 번호를 알 수 없음 → 사용자에게 묻는다. 추측해서 파일을 만들지 않는다.
- 머리말 모양이 틀린 파일 → 검사 명령이 파일과 줄을 알려 준다. 다시 풀기·요약 계산에서 그 파일은 빼고 빠졌다고 알린다(조용히 넘기지 않는다).
- 같은 문제 번호가 저장소에 여러 개 있음(예: 예전 중복 파일) → 어느 것을 이어 쓸지 사용자에게 묻는다.
- 같은 날 같은 문제를 두 번 끝냄 → 기록 줄이 두 줄 생긴다(그대로 둔다).

## 확인 방법 (필수)

- 검사 명령이 원래 없었다. 새로 `python3 -m unittest discover -s tests`를 둔다(표준 라이브러리만 사용, 네트워크 없이 돈다). 0이어야 통과.
- 테스트로 반드시 확인할 것: 머리말 읽기/쓰기 왕복, 틀린 머리말 거절(줄 번호 포함), 다시 풀기 일정의 모든 경우(첫 통과, 실패 후 3→7→30→없음, 중간 실패 시 3일로, 밀린 복습 정렬, 실제 푼 날 기준), 점검 차례 판정(첫 기록 7일 전/후, 마지막 점검 7일 전/후, 유형 없음), 점검 유형 고르기, 점검 통과 판정(0단계·30분·풀었음 경계: 30분 통과, 31분 미통과, 1단계 미통과), 요약 계산(빈 저장소, 예전 파일 무시), 커밋 대상이 코치 파일만인지.
