# plan — 코딩테스트 코치

## 큰 그림

코치는 두 부분이다.
- **코치 설명서**(Claude Code 스킬, `/coach`로 부름): 힌트 주는 법, 대화 흐름, 언제 어떤 명령을 부르는지.
- **작은 파이썬 도구**: 날짜 계산, 머리말 읽기/쓰기/검사, 다시 풀기 목록, 점검 차례, 요약, 진행 중 문제 기억, 커밋·푸시. 계산이 틀리면 안 되는 부분을 대화가 아니라 코드와 테스트로 맡긴다.

순수 계산(`coach/logic/`)은 파일·깃·시간을 직접 모르고 값만 받는다. 파일 읽기·깃·현재 날짜는 명령 도구(`coach/cli.py` 쪽)만 한다. 가져오는 방향은 cli → logic 한쪽이다.

제안 자리(구현자가 저장소를 보고 조정 가능):

```
.claude/skills/coach/SKILL.md   코치 설명서
coach/logic/types.py            유형 목록(유일한 자리)
coach/logic/header.py           머리말 읽기·쓰기·검사
coach/logic/schedule.py         다시 풀기 일정
coach/logic/progress.py         점검 차례·유형 고르기·통과 판정·숫자 요약
coach/cli.py (+ 필요하면 coach/repo.py)   명령 도구
tests/                          테스트
notes/patterns.md               유형 노트
```

## 작업

### T1 — 유형 목록과 머리말
- 목표: spec의 유형 목록을 한 곳에 두고, spec "머리말 — 정확한 모양"대로 머리말을 읽어 값(사이트, 번호, 제목, 링크, 유형들, 막힌 곳, 핵심, 기록 줄들, 다음 복습)으로 바꾸고, 그 값을 다시 똑같은 글로 쓴다.
- 지켜야 할 것: 읽고 쓰면 글자 하나 다르지 않다(왕복). 모양이 틀리면 몇째 줄이 왜 틀렸는지 알려 주는 오류. 목록 밖 유형, 첫 유형과 폴더 불일치, 힌트 0~5 밖, 음수 분, 날짜 형식 틀림, 구분자 틀림은 모두 오류. 머리말 없는 파일(예전 파일)은 오류가 아니라 "머리말 없음"으로 구별한다.
- 대상: `coach/logic/types.py`, `coach/logic/header.py`, `tests/`.
- 확인: 검사 명령 통과, 위 경우마다 테스트(정상·오류·경계).

### T2 — 다시 풀기 일정
- 목표: 한 문제의 기록 줄 목록 → 다음 복습 날짜 또는 없음. 여러 문제 + 오늘 날짜 → 오늘까지 다시 풀 목록(가장 오래 밀린 것부터).
- 지켜야 할 것: spec "다시 풀기 일정" 그대로. 통과=풀었음·2단계 이하, 실패=3단계 이상 또는 못 풀었음. 마지막 실패 이후 연속 통과 k: 0→3일, 1→7일, 2→30일, 3 이상→없음. 실패가 없으면 없음. 날짜는 그 시도 날짜 기준.
- 대상: `coach/logic/schedule.py`, `tests/`.
- 확인: 검사 명령 통과. 첫 통과, 2단계 통과·3단계 실패 경계, 3→7→30→없음, 중간 실패 재시작, 밀린 복습 정렬, 빈 목록.

### T3 — 점검과 숫자 요약
- 목표: (1) 점검 차례인지: 마지막 점검 + 7일, 점검 없으면 첫 기록 + 7일, 기록된 유형 없으면 아님. (2) 점검 유형 고르기: 푼 적 있는 유형 중 점검 안 한 유형 먼저, 그다음 마지막 점검이 가장 오래된 유형, 같으면 유형 목록 순서. (3) 점검 통과 판정: 0단계·30분 이하·풀었음. (4) 숫자 요약: spec "실력 숫자 요약" 항목들(유형별 최근 점검 결과, 최근 4주 주별 평균 힌트 단계·평균 시간, 주별·유형별 푼 문제 수). 유형은 각 문제의 현재 대표 유형으로 센다(유형을 바꾸면 예전 기록도 새 유형).
- 대상: `coach/logic/progress.py`, `tests/`.
- 확인: 검사 명령 통과. 7일 경계(6일 아님, 7일 맞음), 유형 없음, 30분 통과·31분 미통과·1단계 미통과·못 풀었음 미통과, 빈 입력 요약.

### T4 — 명령 도구
- 목표: Claude가 코치 설명서에서 부르는 명령들. 출력은 Claude가 읽기 쉬운 글(또는 JSON, 구현자가 정하고 설명서에 적음). 최소한:
  - `today`: 진행 중 문제, 오늘까지 다시 풀 목록, 점검 차례와 고를 유형.
  - `find <사이트> <번호>`: 저장소에서 그 문제 파일 찾기(새 규칙·예전 파일 모두, 번호로). 여러 개면 모두 보여 줌.
  - `start` / `stage` / `abandon` / `current`: 진행 중 문제 기억(시작 시각, 최고 단계, 점검 여부). 로컬 파일에 저장하고 `.gitignore`에 넣는다.
  - `finish`: 기록 줄 하나 더하기(분은 시작 시각부터 내림 계산), 다음 복습 다시 계산, 머리말 쓰기, 필요하면 파일 새 자리로 옮기기(예전 파일·유형 바뀜, 깃 기록이 이어지게), 진행 중 기억 지우기.
  - `stats`: 숫자 요약.
  - `check`: 모든 머리말 검사, 틀린 파일과 줄 출력, 틀린 게 있으면 0이 아닌 종료 코드.
  - `save`: 코치가 이번에 쓴 파일만 커밋(메시지 규칙은 spec)하고 푸시. 실패하면 실패라고 출력하고 0이 아닌 종료 코드.
- 지켜야 할 것: 커밋에 다른 파일이 섞이지 않는다. 머리말이 틀린 파일은 계산에서 빼되 빠졌다고 출력한다. 현재 날짜·시각은 이 층에서만 얻는다.
- 대상: `coach/cli.py`(+ 필요하면 `coach/repo.py`), `.gitignore`, `tests/`.
- 확인: 검사 명령 통과. 임시 저장소를 만들어 `finish`·`save`가 코치 파일만 커밋하는지, 예전 파일 옮기기, 틀린 머리말 보고, 푸시 실패 시 종료 코드(원격 없는 임시 저장소)를 테스트.

### T5 — 코치 설명서와 문서
- 목표: `.claude/skills/coach/SKILL.md`에 spec "코치 대화 흐름"·"힌트 단계"·"점검 문제"·"유형 노트"·"저장·커밋·푸시"·"예외 규칙"을 Claude가 따를 지시로 쓴다. 각 순간에 부를 T4 명령을 적는다. 사용자에게는 쉬운 한국어로 말하게 한다. `notes/patterns.md` 뼈대(유형 목록 순서로 절 제목만). README의 "파일명은 문제 번호로" 부분을 새 규칙으로 바꾸고 "예전 파일은 옛 규칙, 다시 풀 때 옮김" 한 줄과 `/coach` 쓰는 법 몇 줄을 더한다. `.gitignore`에 `__pycache__/`가 없으면 더한다.
- 지켜야 할 것: 5단계 전 정답 코드 금지, "다음" 없이 단계 올리기 금지, 점검 중 힌트 한 번 묻기, 유형·노트는 사용자 확인 후 확정. README의 나머지 문장은 건드리지 않는다.
- 대상: `.claude/skills/coach/SKILL.md`, `notes/patterns.md`, `README.md`, `.gitignore`.
- 확인: 검사 명령 통과 + `check` 명령 통과. 설명서가 T4 명령 이름과 맞는지 대조. 끝난 뒤 사용자가 문제 하나를 실제로 풀어 본다(사람 확인).

## 순서 설명

T1(머리말)이 모든 계산의 바탕이다. 일정(T2)과 점검·요약(T3)은 머리말 값만 쓰므로 함께 진행할 수 있다. 명령 도구(T4)는 셋을 모두 쓴다. 설명서(T5)는 명령 이름이 정해진 뒤 쓴다.

공유 파일 안내: `.gitignore`는 T4가 진행 중 기억 파일을, T5가 `__pycache__/`를 더한다. 두 작업은 순서가 정해져 있어 겹치지 않는다. `tests/`에는 작업마다 다른 파일을 만든다.

```yaml
tasks:
  - id: T1
    depends: []
    risk: RISKY
  - id: T2
    depends: [T1]
    risk: RISKY
  - id: T3
    depends: [T1]
    risk: RISKY
  - id: T4
    depends: [T1, T2, T3]
    risk: RISKY
  - id: T5
    depends: [T4]
    risk: MECHANICAL
regen_barriers: []
```
